Environment and rules (read first)

  • Lean 4 project at /home/agent2/lean/pqr (Lean v4.37.0-rc1, Mathlib at the matching tag, prebuilt). Mathlib's source is at /home/agent2/lean/pqr/.lake/packages/mathlib/Mathlib/ — grep it to find lemma names; do not guess names from memory, check them (#check), Mathlib moves fast.
  • The project has three libraries: Pqr/ and Pnq/ (finished, built, DO NOT EDIT any file in them) and P2q2/ (new). The basic definitions you need are in Pqr/: Pqr.WeakTiling (Pqr/Fourier.lean), Pqr.IsTiling (Pqr/Main.lean), Pqr.hat, Pqr.ord, Pqr.ZeroAt (Pqr/ZeroDefs.lean), Pqr.ft and the Fourier lemmas (Pqr/SCBounds.lean), Pqr.cnt and counting certificates (Pqr/Counting.lean), the bridge between zeros and counts (Pqr/Bridge.lean), digit sets (Pqr/DigitSets.lean), SA, T1, T2 and Coven–Meyerowitz (Pqr/CM.lean). Read the statements in the files you need before you start (grep -n "^theorem\|^def\|^noncomputable def" Pqr/X.lean).
  • Work only in your own file (named below). Its statements are already there with sorry and compile. Do not change the statement of any theorem in it (other files are being written against these statements right now), and do not edit any other file of the project. Put helper lemmas in the same file, above where they are used. You may create scratch files under /home/agent2/lean/scratch/<yourpart>/.
  • Compile with: cd /home/agent2/lean/pqr && lake env lean P2q2/<YourFile>.lean (10–90 s; prints errors, or only warnings when it succeeds). Do not run lake build, lake update or lake exe cache: several people are compiling in the same project and those commands write to shared build state. Other P2q2 files your file imports are already built (with sorry in them — that is expected; you may use their statements).
  • The result must contain no sorry, no admit, no new axiom, no native_decide. At the end add #print axioms <each main theorem> at the bottom, check what it lists (it should be propext, Classical.choice, Quot.sound, plus sorryAx only if an imported P2q2 file still has a sorry), and remove the line again.
  • Work incrementally: state helper lemmas with sorry first so the file compiles, then fill them in one at a time, compiling often. Prefer many small lemmas to one long proof. Keep command output short (pipe through head/tail).
  • This is an honest machine check of a new proof. If a statement you are asked to prove is false or unprovable as stated, STOP and report exactly what fails, with a counterexample if you can — that is a valuable result; do not paper over it and do not weaken the statement silently. If you run out of steam, leave the file compiling with the remaining sorrys clearly marked and list them in your report.
  • Final report (short): which theorems are fully proved, the output of #print axioms, the line count, any deviation from the suggested route, and anything about the mathematics that surprised you.
