Review of the two necessary conditions in neck2.c (agent3)

agent2 asked for a second pair of eyes on the two conditions used to screen candidates before the linear program. I re-derived both from the definition without looking at agent2's derivation (which is not in the README), read neck2.c, and ran an independent brute-force check. Both conditions are correct, the code applies them in the safe direction, and neither can be tightened by a constant.

Setting. A ⊂ Z_M, n = |A|. f real on Z_M with f(0) = 1, f ≥ 0, f̂ ≥ 0, 1_A ∗ f = 1. Transform ĝ(ξ) = Σ_z g(z) e^{−2πiξz/M}, so the constant function 1 has transform M·δ₀.

Two facts used by both conditions:

  • Taking transforms of 1_A ∗ f = 1 gives 1̂_A(ξ)·f̂(ξ) = M·δ₀(ξ). At ξ = 0 this is n·f̂(0) = M, so Σ_z f(z) = f̂(0) = M/n. At ξ ≠ 0 it forces f̂(ξ) = 0 unless 1̂_A(ξ) = 0, so f̂ is supported on {0} ∪ Z, where Z is the set of nonzero Fourier zeros of A.
  • |f̂(ξ)| ≤ Σ|f| = f̂(0) because f ≥ 0, and |f(z)| ≤ (1/M)Σ|f̂| = f(0) because f̂ ≥ 0.

(a) |Z| ≥ n − 1. Inversion at 0: 1 = f(0) = (1/M) Σ_ξ f̂(ξ) = (1/M)(M/n + Σ_{ξ∈Z} f̂(ξ)), so Σ_{ξ∈Z} f̂(ξ) = M(n−1)/n. Each term is at most f̂(0) = M/n. Hence |Z| ≥ n − 1. ∎

(b) |A − A| ≤ M − M/n + 1. Evaluate 1_A ∗ f = 1 at a point a₀ ∈ A: Σ_{a∈A} f(a₀ − a) = 1. The term a = a₀ is f(0) = 1 and the rest are ≥ 0, so f(a₀ − a) = 0 for every a ≠ a₀: f vanishes on (A − A) ∖ {0}. So f is supported on at most M − |A − A| + 1 points, and on each f ≤ f(0) = 1. Therefore M/n = Σ f ≤ M − |A − A| + 1. ∎

Each uses all three hypotheses (f ≥ 0, f̂ ≥ 0, f(0) = 1), as the README says.

The code

  • Zeros. For each divisor d ≥ 2 of M the mask polynomial is evaluated at one primitive d-th root of unity and, if it vanishes, φ(d) is added. That is right: the polynomial has integer coefficients, so it vanishes at one primitive d-th root iff at all of them, and the frequencies of order d number φ(d).
  • Numerical threshold. A value is called zero when its squared modulus is below 10⁻¹⁸. Round-off on a sum of ≤ 42 unit terms is ~10⁻¹⁵ in modulus, so a true zero is never missed. In principle a nonzero value could fall below 10⁻⁹ (a nonzero algebraic integer can have one small conjugate), which would over-count zeros — but that only makes the screen keep a set it could have rejected, and that set then goes to the linear program. So the only possible error is in the harmless direction.
  • Difference set. diff |= rotate(b, −i) over i ∈ A builds A − A (the i = 0 shift by M is masked to nothing, as it should be). The comparison uses real division M/|A|, which matters when |A| ∤ M.
  • What I did not check: the necklace generator beyond recognising it as the standard one and noting that your class count matches the formula; pdc.py, the linear program, or the tiling backtracker.

Independent check (review-agent3-check.py)

Every set that properly tiles must pd-tile, so it must satisfy both conditions. With my own tiling test (not yours) I enumerated every tiling set containing 0 for M = 12, 16, 18, 20, 24:

No violations, and both bounds are attained by most tiling sets, so neither has slack to give. (My counts are larger than your first table's — 88 against 55 at M = 12 — which I take to be your "cheap symmetry cut"; I count every tiling set that contains 0.) This checks that the conditions are necessary, which is the property the screen relies on. It says nothing about how much they prune.
