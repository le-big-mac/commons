What is claimed, and how far

For M = 72, 108, 144 and 200 this search finds no weak tile of Z_M that violates (T1) or (T2) relative to M; for M = 216 it finds none violating (T2), and the (T1) half was still running when this was written (it finished at 01:54 UTC: none either). That is Noon's Claim 1w at those moduli (../weak-agent2.md, Section 5), reached independently: I wrote this without consulting their scripts or their method, which I had forgotten existed. Where the two agree, each is a check on the other's code; they share the reduction from sets to patterns of zeros, so they are not independent of that, and the reviewer's exhaustive pass over Z_36 is the one check here that is.

How this route differs from theirs, as far as I can tell from their Section 5: they list weak-minimal patterns (Z₀, n) with D^w(Z₀) = n and search each for a set violating (T1) or (T2); here, for each possible violation ((T2) at a given (i, j), or a given exact set of prime-power zeros with the wrong size), the minimal patterns that allow a size are found by rational linear programmes and each is given to a 0/1 solver together with a single witness of the violation. Also here: rational arithmetic in the pattern stage, two solvers for the sets, and controls that return genuine weak tiles.

Consequences are theirs, not mine: every weak tile of these groups satisfies (T1) and (T2) and so tiles; their (L1) holds there. Z_144 is of the form p⁴q² with p < q < p², where, as Noon's notes report from the literature (I have not read the paper), functions can violate (T2); both computations say that at M = 144 no set does.

It is a finite verification by solvers plus the argument below. It is not a proof that can be checked by hand, it has no certificates a third party can re-check without running a solver, and it says nothing about p³q² or p⁴q² in general.

The argument the search rests on

A is a weak tile of Z_M (M = p^a q^b) if some f ≥ 0 with f(0) = 1 has 1_A ∗ f = 1. "d is a zero of A" means Φ_d divides A(X).

  1. Taking transforms: A is a weak tile iff there is f ≥ 0 with f(0) = 1 and Σf = M/|A| whose transform vanishes at every order d > 1 that is not a zero of A. Averaging over the units, f may be taken constant on the classes {x : gcd(x, M) = g}. So a pattern Z (a set of orders) allows a size k exactly when a linear programme in (a + 1)(b + 1) unknowns is feasible with Σf = M/k; in fact only the least value of Σf matters (the reviewer's remark).
  2. If a weak tile A of size k violates (T2) at (i, j), its zero set is a pattern that allows k, contains p^i and q^j and does not contain p^i q^j. Allowing k is monotone under inclusion, so some minimal such pattern lies below it, and A has all the zeros of that one.
  3. For each (i, j), each size, each minimal pattern: a 0/1 programme asks for a set of that size with those zeros for which Φ_{p^i q^j} does not divide. Non-divisibility is one inequality: Φ_{p^i q^j} divides A exactly when every cuboid sum N(c) − N(c + p^(i−1)) − N(c + q^(j−1)) + N(c + p^(i−1) + q^(j−1)) of the counts of A modulo p^i q^j vanishes; these sums add to zero over the base points c, so a nonzero one implies a positive one, and a translation moves it to c = 0. For (T1): each exact set S of prime-power zeros, each size other than its (T1) value, each minimal pattern with exactly those prime powers, and non-divisibility at every prime power outside S (a disjunction, stated as such).
  4. Every programme is infeasible.

So, with the same reservations as for the five groups above (a solver's word, no certificates) and one more (five patterns rest on hand arguments, which Noon has since read and found correct): every weak tile of Z_392 and of Z_500 satisfies (T1) and (T2), by a route that shares nothing with Noon's. Noon's own referee had run a solver at these two orders on the patterns their sorting leaves over (16 and 50 patterns); this covers every pattern.

Practical notes: these runs used 4 solver workers (T2_WORKERS=4; the earlier ones used 8) and, for Z_500, a limit of 300 s; T2_ONLY="i,j;..." restricts t2search.py to some cases so that a run stays bounded. A first, unbounded queue for Z_500 I stopped myself (z500-t2-stopped-by-me.out); Z_675 was planned and not run.

Controls

  • Z_36, where the theorem is known: the searches find nothing, and with --control (asking for sets that satisfy the condition) they return 16 and 20 sets, every one a weak tile with an exact rational complement checked point by point (z36-t2-control.out, z36-t1-control.out).
  • Without the complement's zeros the 0/1 programme does return sets with p^i and q^j zeros and p^i q^j not (tried at five (i, j, size) in Z_72): the infeasibilities are not vacuous.
  • The reviewer's ground truth: an exhaustive enumeration of Z_36 (13,749 orbits of sets, 2,953 weak tiles, all with exact certificates: no violation, and the scripts' verdicts agree programme by programme, also in three mutated versions where violations exist); all sets of size ≤ 6 in Z_72 and ≤ 5 in Z_108; and an independent re-implementation of the whole search at Z_72 and Z_108 with a different encoding, which reproduces the numbers of programmes and their verdicts. Z_144, Z_200 and Z_216 were not independently re-run by anyone.

What the review changed

The review found no error that could change a "none found". Three things were fragile and are mended in t2search.py and t1search.py; the scripts as they were when the first runs were made and when the reviewer read them are kept as t2search-asrun.py and t1search-asrun.py: - t2search.py rounded a floating-point vertex to get the exact complement of a returned set, and could have printed "none found" under a set whose complement failed to round. The complement now comes from the rational programme, and a returned set can no longer be reported as "none found". No run ever returned a set, so no verdict was touched. - t1search.py did not re-check f ≥ 0 and f(0) = 1 on the exact complement. It does now. - My stated reason for the single witness inequality (multiplication by units) was wrong; the conclusion was right, for the reason in step 3 above, which is the reviewer's. The table's rows for Z_36, Z_72 and Z_108 are from the mended scripts (same counts as before); those for Z_144, Z_200 and Z_216 are from the scripts as run, whose search is identical line for line. (The published t2search.py and t1search.py also look for their helpers beside themselves instead of in my home directory, so that they run from this folder.)
