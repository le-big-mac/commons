Review of t2search.py, t1search.py and exactlp.py

Verdict. I found no error in the three scripts that could change a "none found". The conclusion that every weak tile of Z_72 and Z_108 satisfies (T1) and (T2) survived every check I ran. There are a few fragile spots, listed at the end; none affected the published runs.

No existing file was modified. All scratch code and logs are in /tmp/rev_t2. The scripts' own functions were tested by executing their source text in memory, cut before the search loop, or with one-line textual patches where stated.

(a) The reduction, the matrix Tm and the linear programmes

By reasoning: correct. - Taking transforms of 1_A * f = 1 gives |A|·Σf = M at frequency 0. At ξ ≠ 0 it gives "A has a zero at the order of ξ, or f^(ξ) = 0". So f ≥ 0, f(0) = 1, Σf = M/|A| plus the support condition is exactly equivalent to a weak complement. - Averaging f over x → ux keeps f ≥ 0, f(0), Σf, and the set of orders where the transform vanishes. The orbits of the units are exactly the gcd classes, so class-constant f is legitimate, and one equation per order (at ξ = M/d) suffices. - Tm sums cos(2πxξ/M) over each class at ξ = M/d, which is that equation. Class (a, b) is {0}. The programmes state the right constraints.

By code. - Tm, class sizes and classes of both scripts equal an independent FFT computation at every frequency of each order, for M = 36, 72, 108, 144, 200. - Floating-point and rational sumf_range agree on all patterns for M = 36, 72, 108, 200 (256 / 2048 / 2048 / 2048 patterns): no status mismatch, endpoints within 7e-14, identical allowed-size lists. - For Z_36, on all 13,749 sets of the exhaustive pass in (g): "the script's pattern programme for the exact zero set allows |A|" coincides with the certified weak-tile verdict, in both arithmetic modes. - A full LP on all M unknowns agreed with my own class-constant LP on every set tried: 13,749 (Z_36), 79,751 (Z_72), 29,994 (Z_108) and 1,932 sampled sets.

One observation. The pattern programme is never infeasible (f ≡ 1 always works), and Σf is unbounded above for every nonempty pattern. So the upper LP and the return None branch carry no information; the content is the lower bound alone. This is harmless.

(b) Completeness of steps (2)–(3)

By reasoning: sound. - "Z allows k" is monotone under inclusion, so a violator's exact zero set lies above a minimal allowed pattern of the same family. A translate of the violator then satisfies that programme. - range(2, M) loses nothing: k = 1 has no zeros and k = M has all of them. - Unbounded Σf is handled correctly in both modes. - Y < Z is proper inclusion, which is the right filter. - The 1e-7 tolerance can only add patterns, which is safe.

By code. - End to end on Z_36 against the ground truth of (g): every programme verdict of t2search agrees (139 programmes, in both solver modes). - Three mutation runs with weakened hypotheses, where violations do exist, also agree: 211 / 154 / 265 programmes with 23 / 22 / 78 feasible, each exactly where the ground truth has a weak tile. - My independent replication (see "Independent replication" below) reproduces the per-(i, j) counts of minimal pairs exactly: 227, 205, 196, 154, 201, 126 for Z_72 and 235, 200, 180, 260, 190, 132 for Z_108.

(c) The cuboid witness

By reasoning: true, and slightly more than claimed. - For each fixed (s, t), the cuboid functional is a convolution whose transform is supported exactly on the characters of order p^i q^j. So Φ_{p^i q^j} divides A iff all cuboids with that one (s, t) vanish; s = t = 1 alone suffices. - The (1, 1)-cuboids sum to zero over c, so a nonzero one implies a positive one, and a translation moves it to c = 0. - Translation preserves |A|, every zero and weak-tile-ness. Units are not needed. - The docstring's wording ("multiplication by units … make it positive") is not the right reason, since x → −x does not change the sign. The conclusion wit >= 1 is still justified.

By code. - M = 72: 880 sets (random, coset-built, and 80 from 0/1 programmes with prescribed zeros), 5,280 (set, i, j) tests. Divisibility agreed with "all cuboids vanish" in all, and with s = t = 1 only in all. A normalised witness was found in all 4,024 non-divisible cases, each time by a translation alone, with size and exact zero set unchanged. - M = 108: 886 sets, 5,316 tests, 4,035 non-divisible cases, same result. - Also clean on M = 36, 144, 200, 45. A seventh modulus (35) was not run because of a bug in my own generator.

(d) residues(d, M)

By reasoning: it computes X^x mod Φ_d by repeated multiplication by X, so R·1_A = 0 iff Φ_d divides A.

By code: 124,500 (set, d) pairs over M = 36, 72, 108, 144, 200, 216, 100, 45, of which 27,649 are zeros. It agrees with divides, with evaluation at a root of unity, and with the FFT at all frequencies of the order, with zero disagreements.

(e) exactlp.py

By reading: I found no error in phase 1, the removal of artificials (pivoting on any nonzero entry of a zero-level row is valid), the dropping of redundant rows, Bland's rule for both entering and leaving variables, or the unbounded test.

By code: 9,000 programmes in four new families (degenerate, redundant/inconsistent, fractional, script-shaped). Status and exact optimum were compared with an independent rational vertex enumeration and with HiGHS: zero disagreements.

An instrumented in-memory copy shows the delicate paths were exercised: - 713 drive-outs of artificials, 609 of them on negative pivots; - 2,787 redundant rows dropped; - over 12,000 degenerate pivots.

The real pattern programmes are about 90% degenerate pivots and never redundant.

(f) t1search.py

By reasoning: correct and complete. - Φ_{r^e} divides A iff the counts mod r^e are constant on classes mod r^(e-1), so the disjunction is the right encoding. - A violator is caught in the iteration of its own exact prime-power set S. Sets with more prime-power zeros than S are excluded there and handled under their own S, so nothing is missed.

By code. - The encoding agrees with divides on 42,000 (set, prime power) pairs. - On Z_36 all 257 programmes agree with the ground truth. --control gives 24 programmes with 20 feasible, all correct. - With the size filter removed (281 programmes), every ground-truth (size, zero set) is covered, and nothing is feasible at a non-(T1) size.

(g) Independent spot check by a different method

Each set was decided by the LP on all M unknowns. A weak tile counts only with an exactly verified rational complement; a non-tile, where stated, with an exactly verified Farkas vector.

Z_36, exhaustive. - All 224,488,590 sets containing 0 with A − A ≠ Z_36 were enumerated; a set with full difference set forces f = δ_0. - 1,346,178 pass the support test, giving 13,749 orbits under x → ux + t. - 2,953 orbits are weak tiles and 10,796 are not, all with exact certificates. - Weak-tile sizes are 2, 3, 4, 6, 9, 12, 18, with 62 distinct (size, zero set) types. - (T1) violations: 0. (T2) violations: 0. - The enumeration pipeline was validated by brute force on Z_12 and Z_18 (131,070 sets): identical orbit lists.

Z_72. - Exhaustive for sizes ≤ 6: 79,751 orbits, 2,372 weak tiles, all certified, no violation. - Targeted sample of 965 sets up to size 36: 360 (T2)-violating sets (none a weak tile), 140 built to violate (T1), plus tiles and near-tiles. No weak tile violates either property.

Z_108. - Exhaustive for sizes ≤ 5: 29,994 orbits, 220 weak tiles, no violation. 26,135 of the negatives rest on HiGHS only. - Size 6: all 17,171 (T2)-violating orbits are non-tiles (1,361 certified, the rest HiGHS only). (T1) at size 6 was not covered. - Sample of 967 sets: no violation.

Independent replication at all sizes. This uses my own pattern code, a count/cuboid encoding instead of residues, and the witness as a full disjunction. It shares the pattern reduction with the scripts, so it is a check on the implementation rather than on the reduction itself. - (T2): 1,109 (Z_72) and 1,197 (Z_108) programmes, all infeasible by CP-SAT. - (T1): 1,551 and 1,602 programmes, all infeasible by HiGHS with big-M. By CP-SAT, all infeasible except one programme that hit the time limit (see item 3 below).

Other fragile points

  1. t2search.py line 71 and lines 128–131. exact_complement rounds a floating-point vertex with limit_denominator(10**6). If that fails, the set is printed with "complement: no" and the last line still says "none found". In a non-control run, any returned set is by construction a weak tile violating (T2), so the verdict should require found to be empty and the complement should come from exactlp. This had no effect on the published runs, which all report "0 with a set". The function was right on all 13,749 Z_36 sets.

  2. z108.out, the two HiGHS lines. Both come from one programme: (i, j) = (1, 2), k = 18, pattern {2, 9, 12, 27, 36, 108}. As I read the message, HiGHS found a point it took for feasible after presolve and had to repair it. It still returned infeasible, and CP-SAT confirms. The CP-SAT runs are the ones to cite.

  3. t1search.py line 55, worker dependence. One Z_108 programme (k = 18, zeros 3, 9, 54) was not decided in 300 s by the script's own find() with 3 workers; the published 8-worker run decided it. It would be reported as undecided, so the failure is not silent. Split by symmetry into four cases, it is infeasible in 0.1 s under both solvers.

  4. t1search.py line 64. exact_complement does not re-check f ≥ 0 and f(0) = 1; it relies on exactlp for both.

  5. No certificates. Every infeasibility is a solver's word. Z_144 I only read; I did not re-run it.

Two of my own runs exceeded the CPU budget you set: one took 8.5 minutes on 4 cores, and one was stopped after 10 minutes.
