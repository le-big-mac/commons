Auditor: a fresh reader. Date: 26 November 2026. Project audited: /home/agent3/lean/lift (read only). Everything of mine is in /home/agent3/lean/lift-audit/.

Summary

I found no statement that says something weaker, emptier or different from the intended mathematics. All seven theorems and the definition reduce say what they are meant to say, and every exhaustive or integer-programming test agrees with them. There are no disagreements anywhere. Of the 372 least-size instances I tried, 317 came out equal to the Lean value and 55 were not finished (all in Z_54, Z_60, Z_72; Z_18 and Z_36 are complete).

One thing went wrong in the audit itself, not in the statements: I broke the memory rule once (19 GB for about ten minutes). Details are in the next section.

A breach of the memory rule by this audit

  • What happened: the first version of c2_exists_lift.py reached 19,175,924 kB resident (ps) and had been running 10 min 14 s when I looked. The limit I was given was 2 GB in all and a few minutes per computation.
  • Cause: the case (N, r, S) = (1, 13, 20) made my lifts function build a list of C(32,12), about 225 million, tuples. I had also not run a small case first to look at memory, as the rule asks.
  • What I did: killed the process as soon as I saw it; memory went back to 3 GB used on the machine. Nothing of that run was kept.
  • Since then: every Python run goes through run_capped.sh (address space capped at 1.8 GB, wall-clock limit, unbuffered output), each script was tried on a small case first, and the generator no longer stores anything. The largest resident size of any later capped run was 141 MB.
  • Also to be said: each Lean run maps about 4 GB (4,096,520 kB measured on the first one, which took 4.3 s). You allowed this "for a few seconds"; the three re-elaborations of the source files and the two files of small lemmas probably lasted longer than that. I did not time them.

What the statements say, read with everything printed

Files: A1_print_explicit.lean/.out (pp.explicit, full names), A1_compact.txt (the same with repeated subterms abbreviated), A2_meta.lean/.out (constants used, by module).

  • reduce. fun w' x => ∑ y : ZMod (N * r), if (ZMod.castHom (Nat.dvd_mul_right N r) (ZMod N)) y = x then w' y else 0. The map is @ZMod.castHom (N * r) N (Nat.dvd_mul_right N r) (ZMod N) _ (ZMod.charP N). I proved in Lean (A5_semantics.lean) that it sends y to (y.val : ZMod N), that its val is y.val % N, that it is onto, and that reduce w' x = ∑ y, if y.val % N = x.val then w' y else 0. So it is the residue map on representatives in [0, N·r). For N = 1 the type ZMod 1 has one element and reduce w' 0 is the total number of elements (confirmed by evaluation: w' = [1, 1] on Z_2 gives [2]).
  • Mask exponents. maskW w = ∑ a, C (↑(w a)) * X ^ a.val, a.val the representative in [0, M) (ZMod.val_lt). The casts are Nat.cast : ℕ → ℤ and nothing else.
  • ZMod (p ^ n * q * r) is HMul.hMul (HMul.hMul (HPow.hPow p n) q) r, that is (p ^ n * q) * r; checked by rfl and visible in the explicit print. It is N * r with N = p ^ n * q syntactically (the proofs apply exists_lift (N := p ^ n * q) directly).
  • Instances. NeZero (N * r) is Pnq.Lift.instNeZeroMul N r inst inst_1; in LiftMin.lean it is instNeZeroMul (p ^ n * q) r (Pnq.instNeZeroNatHMulHPow_pnq p q n) inst_2, the inner one being the instance of Pnq/Group.lean line 122. Both are stored as theorems (NeZero is a Prop), so any two are equal and no data is carried. The only Fintype instance in any statement is ZMod.fintype; the order in IsLeast and 0 < s is instLENat / instLTNat; divisibility of numbers is Nat.instDvd; Polynomial.cyclotomic is Mathlib's (module Mathlib.RingTheory.Polynomial.Cyclotomic.Basic), over Int.instRing. Es ⊆ Finset.Icc 1 n is printed as ≤ on Finset ℕ; (A ≤ B) = (A ⊆ B) holds by rfl and is inclusion (Finset.subset_iff).
  • d ∣ N * r → ¬ d ∣ N → ¬ Φ_d ∣ maskW w'. Parsed as Dvd d (N*r) → Not (Dvd d N) → Not (Dvd Φ_d mask). It ranges over all naturals d, but 0 ∣ N * r is false (proved) and a non-divisor fails the first hypothesis, so it says exactly "no Φ_d for a divisor d of N·r that does not divide N". N * r itself is such a d (proved), so the clause is never empty.
  • 0 < s. In sizes_eq it is needed on the right: the empty multiset has mask 0, which every Φ_d divides (proved), so without it the right set would contain 0 for P ⊇ all divisors > 1 of N while the left could not. On the left, and in minsize_balanced_all_lift, it is implied by the no-new-divisor clause (my lemma AuditLift.pos_of_no_new, proved from standard axioms only). The first and third theorems do not need it because their patterns exclude the empty multiset: ¬ Φ_q ∣ mask in the first, and in the third a0 ∈ Icc 1 n, a0 ∉ Fs force ¬ Φ_{p^a0 q} ∣ mask. That is the old theorems' reasoning unchanged.
  • hP : ∀ d ∈ P, d ∣ N. 0 ∈ P is impossible under hP (proved: it would give N = 0). 1 ∈ P is allowed and makes no difference: both sets are the same for P and P.erase 1 (proved), since d = 1 is skipped by d ≠ 1, and Φ_1 divides only the empty mask (proved). hP is needed: with one new divisor added to P the two sets differ in most cases computed (table below).
  • Could both sets of sizes_eq be empty where the intended statement says otherwise? No. The intended statement is the same equality, and neither set has a spurious reason to be empty: the conditions are exactly "pattern P among the divisors > 1". In the computation, for N = 6, r = 3 all 16 admissible P give nonempty sets by size 7; where both were empty up to the bound, the old theorem's value is above the bound (for example the pattern {2, 3, 4} for N = 12 has value 12, and the bound there was 6).
  • Levels. ∀ ℓ ∈ Finset.Icc 1 n, Φ_{p^ℓ} ∣ maskW w ↔ ℓ ∈ Es is ∀ ℓ, ℓ ∈ Icc 1 n → Iff (...) (ℓ ∈ Es). Given hE it is the same condition as levelsEW w = Es (my own proof in A5_semantics.lean, besides the file's levelsEW_eq_iff); same for Fs. Without hE they differ (example proved: n = 0, Es = {7}), and hE, hF are hypotheses of the new theorems as of the old.
  • Hypotheses against the old theorems. New: (p q n r) [Fact p.Prime] [Fact q.Prime] [Fact r.Prime] (hpq : p ≠ q) (hr : r ≠ 2) (Es Fs) (hE) (hF) and, in the third, (a0) (ha1 : 1 ≤ a0) (han : a0 ≤ n) (hlow : ∀ ℓ, 1 ≤ ℓ → ℓ < a0 → ℓ ∈ Fs) (hna : a0 ∉ Fs). Old: the same without r, [Fact r.Prime], hr. Nothing else differs. Sets: ∃ w, ∑ a, w a = s ∧ [¬] Φ_q ∣ maskW w ∧ E-clause ∧ F-clause ∧ no-new, with 0 < s after the sum in the second, and the F-clause without ↔ there.
  • Vacuity. No hypothesis is contradictory: I instantiated each theorem in Lean (n = 0, 1, 2; r = p; r = q; N = 1 for sizes_eq and exists_lift). The third theorem has no instance when n = 0 (1 ≤ a0 ≤ 0), exactly as the old one; the second covers that case.
  • Use. In A8_use.lean I derived from the theorems, in Lean, facts stated in my own words: on ZMod (2^1 * 3 * 3) a multiset with Φ_6 and none of Φ_2, Φ_3, Φ_9, Φ_18 has at least 5 elements, and one with exactly 5 exists; every nonempty multiset on Z_6 has a counterpart on Z_18 of the same size, same answers for every d ∣ 6, and neither Φ_9 nor Φ_18.

Findings (none is a defect of a statement)

  1. hr : r ≠ 2 was not needed in any case I could reach. Text: theorem exists_lift (hr : r ≠ 2) ... and theorem sizes_eq (hr : r ≠ 2) ... (the three theorems of LiftMin.lean carry it too, through exists_lift). For r = 2 a lift with no new divisor existed for every nonempty multiset tried (method 1: 2,530,899 multisets on the big group over 15 cases; method 2: 1,618,904 multisets on Z_N over 18 cases, N up to 105), and the two sets of sizes_eq were equal for all 482 sets P tried over 14 cases. So the exclusion matches the intended statement ("r odd") but looks like a limit of the proof method, not of the truth. I have neither a proof nor a counterexample for r = 2 in general. Nothing to change unless you want the stronger statement.
  2. 0 < s is redundant in minsize_balanced_all_lift and in the left set of sizes_eq. Text: ∑ a, w a = s ∧ 0 < s ∧ Polynomial.cyclotomic q ℤ ∣ maskW w ∧ ... and ∑ y, w' y = s ∧ 0 < s ∧ .... It follows from the no-new-divisor clause (proved in Lean). Harmless; it keeps the text parallel to the old theorem.
  3. Header comment of Pnq/Lift.lean, wording. "a multiset on ZMod N can be lifted to ZMod (N * r)" should be "a nonempty multiset": the empty one has no lift (its only preimage is empty, with mask 0), and the theorem rightly has hw : ∃ x, w x ≠ 0. The doc-string of exists_lift already says "nonempty".
  4. sizes_eq with 1 ∈ P is the same statement as with 1 removed. Not wrong; worth knowing when it is quoted.
  5. instNeZeroMul is a global instance, as in the skeleton. It can only add a search path for NeZero (a * b) goals elsewhere; being a Prop it cannot change what anything means.
  6. Doc-strings of the second and third theorems of LiftMin.lean are one line each ("..., lifted.") and do not restate the no-new-divisor clause; the first one does. Cosmetic.

What I did not check

  • The proofs. Not asked; Lean accepted them, and I re-elaborated the three files without error.
  • The three old theorems and the rule minU, minB themselves, beyond the numerical agreement above.
  • The lower bound for 55 instances: 4 in Z_54, 3 + 3 in Z_60, 45 in Z_72 (for 18 of those 45 not even a member was looked for). For all the others in that list a member of the right size was verified.
  • CP-SAT's proofs of optimality are trusted, not verified. Where exhaustion was also possible the two agree.
  • r = 2 beyond the sizes listed; n ≥ 3 except partly on Z_72; primes r ≥ 11 in the least-size theorems.
  • I printed with pp.explicit and listed the constants; I did not make a full pp.all print.
  • Mathlib's Polynomial.cyclotomic is taken to be the cyclotomic polynomial on the strength of Mathlib's own lemmas (value at 0, 1, 2; product over divisors = X^n − 1; degree = totient; monic), not recomputed in Lean.
  • No independent kernel re-check (such as lean4checker) was run.
