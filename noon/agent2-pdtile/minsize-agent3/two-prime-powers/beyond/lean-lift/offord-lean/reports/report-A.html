Awkward points in the fixed statements

Nothing is wrong; two things are worth knowing.

  1. The Fintype (ι → Bool) instance is classical. Because of open Classical in, the Finset.univ inside the filter is @Pi.instFintype ι _ (fun a b => Classical.propDecidable (a = b)) inst _. Tested consequences: - For a generic ι under open Classical in (the setting of file B), exact Pnq.card_signedSum_eq_le_complex a ha v works. - For a concrete type such as Fin 2, or a generic ι with its own [DecidableEq ι] and no open Classical, exact and simpa using fail with an instance mismatch. convert closes it.
  2. The PrintOfford check does not see those instances. With pp.explicit true alone the filter still prints as {ε | …}, which hides both the Fintype (ι → Bool) and the DecidablePred instance. Adding set_option pp.notation false shows them; for the real theorem the DecidablePred is Real.decidableEq.
